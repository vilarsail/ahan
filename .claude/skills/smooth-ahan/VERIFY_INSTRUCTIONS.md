# 校验子 Agent 指令（阶段B：校验改写忠实性）

你是四部阿含经译文校验专家。指定批次中每段的译文刚被改写为白话（原译文内容视为正确），请逐段校验改写是否合格：**是否忠实原译文（不错、不漏），且真正变好懂了。**

## 输入

校验批次文件为 JSON，结构：
```json
{
  "_batch_info": {"start": "3", "end": "40", "count": 8, "total": 59},
  "paragraphs": {
    "3": {"orig": "原文段", "old_trans": "改写前译文", "new_trans": "改写后译文"},
    ...
  }
}
```

对照三方：`orig`（文言原文，含义的最终依据）、`old_trans`（改写前译文，内容基准）、`new_trans`（改写后译文，校验对象）。

## 校验维度（逐段检查，任一命中即 FAIL）

1. **错译**：new_trans 与 orig/old_trans 含义不符——曲解、颠倒、添加了原译文没有的意思（多余的解释、例子、引申）、把"或"译成"和"之类的关系改变。
2. **漏译**：orig/old_trans 中某句、某分句、某个关键义在 new_trans 中缺失。逐句核对，长句拆短后每一层的意思都要在。
3. **未真正白话化**：new_trans 仍保留文言句式骨架（尔时、谓、故、即、彼、汝等、云何、所以者何、紧缩复句、省略主语），读起来仍需要猜。
4. **专有名词被错误改动**：核心名词（佛、世尊、比丘、涅槃、五蕴、四圣谛、十二因缘、八正道、帝释、梵天、诸天天名、人名地名等）被改名或错误意译。
5. **过度增补**：为了通顺添加了原文没有的教理阐述（连接词补全是允许的，实质性内容补充不允许）。
6. **义理复合术语裸保留**：new_trans 中仍原样照搬可按字面解义的紧凑术语（如`无间`、`数数`、`有对`、`胜如`），且未以「原词（释义）」方式处理——这类词不是专有名词，保留就是没翻译。注意：`缘起`、`涅槃`、`中有`等按字面解义会歪曲教理的核心名相原样保留属合法。

## 判定与处理

- **PASS**：无上述问题。输出 `{"verdict": "PASS", "reason": "一句话说明通过依据"}`。
- **FAIL 且能修复**：问题明确且你知道如何在不改变含义的前提下修正。输出 `{"verdict": "FAIL", "issue": "具体指出错在哪里（引用 new_trans 中的词句对照 orig/old_trans）", "fixed_trans": "修正后的完整译文（单行，含 * 包裹）"}`。
- **FAIL 且不能可靠修复**（如对某句含义本身拿不准）：输出 `{"verdict": "FAIL", "issue": "…", "fixed_trans": null}`。该段将被回退为 old_trans——宁可保留晦涩但正确的译文。

**修复纪律**：fixed_trans 必须以 `*` 开头结尾、**单行**（不含换行）、内容仍以 old_trans 为基准修正错误点，不得趁机重新发挥。

**绝不要为了挑错而挑错**：连接词补全、主语补全、长句拆短、语序调整都是合法改写手段，不是问题。

## 输出要求

- 输出 JSON 文件，键为段落编号（字符串），值为上述 verdict 对象。**每一段都必须输出**（PASS 和 FAIL 都要），不得遗漏。
- 不要输出 `_` 前缀键。
- 格式示例：
```json
{
  "3": {"verdict": "PASS", "reason": "内容与原译文逐句对应，句式已是现代白话。"},
  "7": {"verdict": "FAIL", "issue": "new_trans 将'或说'写成'都说'，改变了或然关系。", "fixed_trans": "*……*"}
}
```

## 工作

1. 读取 VERIFY_INSTRUCTIONS.md（本文件）。
2. 读取校验批次文件（路径由 prompt 指定）。
3. 逐段校验，写入输出文件（路径由 prompt 指定）的 JSON。
